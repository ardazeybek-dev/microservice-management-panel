What is actually behind this in the real system

Dynamic authorization

Permissions are rows in role_permissions, not constants in the code. A Supervisor edits the matrix at runtime through PUT /admin/permissions and every subsequent request is checked against the new state.

PostgreSQL · JWT · bcrypt (12 rounds)

Message broker RPC

GET /rpc-test publishes to task_queue with an exclusive reply queue and a correlation id, then waits. A 10-second timeout tears the queue down so a silent consumer can't hang the request forever.

RabbitMQ · amqplib

Audit trigger

Every insert into records writes an audit_logs row from a PL/pgSQL trigger, inside the same transaction — the application cannot forget to log.

PL/pgSQL · GIN index on JSONB

Vector search

Documents are chunked, embedded and stored in a VECTOR(768) column with an HNSW index over cosine distance. Each chunk records which model produced it, because vectors from different models aren't comparable.

pgvector · HNSW · Gemini embeddings

Permission caching

Lookups go through Redis. If Redis is down the server still starts and reads straight from PostgreSQL — the cache is an optimisation, never a dependency.

Redis

Tested

The Express app is built without binding a port, so integration tests drive it through Supertest with no listening server.

Jest · Supertest

Run the real thing

# PostgreSQL (pgvector), RabbitMQ, Redis and the API
git clone https://github.com/ardazeybek-dev/microservice-management-panel
cd microservice-management-panel
cp .env.example .env          # add your Gemini API key
docker-compose up --build
npm run setup-db              # schema + baseline roles, seeds the first Supervisor
